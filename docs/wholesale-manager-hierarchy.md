## 0. 한 줄 요약
도소매 카탈로그를 **멀티테넌트 피라미드**로 재편한다. 최상위 = **도매관리자(도매연합)**, 그 아래 **도매상**, 그 아래 **셀러**. 첫 도매관리자 = **LALAS**. 지금의 `/admin` 대시보드를 **"도매관리자 대시보드"**로 승격하고, **단일 도매업체 대시보드**와 분리한다.

---

## 1. 핵심 구조 (피라미드)

```
                  ┌─────────────────────────┐
                  │   도매관리자 (최상위)      │   ← 1차 = LALAS 1개 (도매연합), 한 명의 도매업자 대표가 운영
                  │   = 테넌트(tenant)        │   ⚪ 먼 미래 = 도매관리자(테넌트)가 여러 개
                  └───────────┬─────────────┘
                 1:n          │
        ┌────────────┬────────┴────────┬────────────┐
        ▼            ▼                 ▼
   도매상 A      도매상 B           도매상 C          ← 각 도매상은 "하나의" 도매관리자에 소속
   (도매업체)    (도매업체)         (도매업체)         상품 등록·관리 주체
        │            │                 │
        └────────────┴────────┬────────┘
                     1:n       │
              ┌───────────┬────┴────┬───────────┐
              ▼           ▼         ▼
          셀러 1       셀러 2     셀러 3          ← 소매(라이브커머스 셀러)
              │
              ├─ 일반 셀러
              └─ 에이전시 셀러 ──1:n──▶ 에이전시 소속 셀러
```

- **도매관리자 1:n 도매상** (도매상은 관리자 하나에 속함)
- **도매상 1:n 셀러**
- **셀러 = 일반 셀러 / 에이전시 셀러**
- **에이전시 셀러 1:n 에이전시 소속 셀러**

## 2. 등장 주체(역할) 정의

| 주체 | 정의 | 비고 |
|---|---|---|
| **도매관리자(도매연합)** | 피라미드 최상위 = **테넌트**. 소속 도매상·셀러의 가입을 **승인·관리**. | 첫 사례 = **LALAS**. **한 명의 도매업자 대표**가 맡아서 운영. |
| **도매상(도매업체)** | 상품을 등록·관리하는 주체. | **하나의** 도매관리자에 소속. `products.wholesaler_id` 가 가리키는 그 도매. |
| **셀러(소매)** | 카탈로그를 보고 주문하는 소매(라이브) 셀러. | **일반 셀러** vs **에이전시 (소속) 셀러**. |
| **에이전시** | **도매가 아님.** 중간관리만 하고 **수수료**를 받음. 자기 소속 셀러를 거느림. | **이 SaaS 의 판매 타깃**(아래 §6-3 참조). |

### 중요 통찰 (사장님 원문 의도)
- **도매관리자 = 테넌트.** LALAS 도 "사실상 에이전시나 다름없이" 도매업체+셀러를 모두 관리한다.
- **SaaS 타깃 = LALAS 처럼 운영하는 에이전시들.** 즉 직접 도매를 하지 않고 **중간관리만 하며 수수료를 받는 에이전시**에게 이 제품을 판다 → 그런 에이전시 각각이 **하나의 도매관리자 테넌트**가 된다.
- 그래서 **LALAS 는 "첫 번째 도매관리자"일 뿐, 시스템은 도매관리자가 여러 개 생기는 멀티테넌트**를 전제로 설계해야 한다.
  - ⏱️ **타이밍**: **실제 다중 도매관리자 운영은 먼 미래.** 1차는 **LALAS 단일 테넌트**로만 동작하고, **설계만** 멀티테넌트를 대비한다(나중에 안 갈아엎게).

## 3. 가시성(노출) 규칙

### 상품 가시성
- **셀러가 도매관리자(LALAS)에 연계되면 → 그 아래 모든 도매상(A,B,C)의 상품을 자동으로 전부 본다.**
  - 예: A·B·C 가 모두 LALAS 소속 도매고, 셀러 1·2·3 이 있으면 → **1·2·3 모두 A·B·C 상품 전체**를 본다.
  - 즉 **"셀러 → 라라스 연계" = 그 라라스 소속 모든 도매업체 상품 노출.**
- ⚪ **[먼 미래]** 셀러별 도매 제한 (예: 셀러 1 은 A·B 만, C 는 못 봄).

### 가격 노출 (기존 규칙과 일치 — CLAUDE.md §가격 노출)
- **일반 셀러**(라라스가 직접 관리) → **도매가 노출 OK**.
- **에이전시 소속 셀러** → **도매가 미노출**.
  - 이유: 에이전시는 **수수료를 붙이는** 구조라, 라라스가 에이전시 소속 셀러에게 **도매가를 공유할 수 없다**.
  - (기존 `seller_type='agency_affiliated' → price_visibility='none'` 규칙이 그대로 들어맞음.)

## 4. UI 재편 (이번 변경의 가시적 핵심)

지금의 `/admin` 단일 대시보드를 **두 개의 대시보드로 분리**한다.

### 4-1. 도매관리자용 대시보드 (지금 `/admin` 을 가져다 재편)
- 가입 승인: **소매/도매가 가입하면 도매관리자 대시보드의 목록에 떠서 승인 여부를 결정**한다.
- **➕ 탭 추가: 상품관리** — 단일 도매업체의 상품관리와 **형식은 똑같이** 가져가되,
  - **소속된 도매상 전체의 상품을 모두 합친 리스트**가 된다.
  - (행마다 **어느 도매 것인지** 표시하면 더 좋음.)

### 4-2. 단일 도매업체용 대시보드 (기존 도매 화면)
- 지금의 도매 상품관리/등록/엑셀 등 = **한 도매업체 관점**의 화면.

> 요약: **도매관리자 대시보드(합산·승인) ↔ 단일 도매업체 대시보드(자기 상품)** 분리.

---

## 5. 기존 모델 대비 변화(델타) — 다음 세션 설계 참고
> ⚠️ 아래는 **개념 수준**이다. 실제 테이블/컬럼/RLS/마이그레이션 설계는 다음 단계에서.

**현재 상태**
- 역할: `admin` / `wholesaler` / `retail_seller`(independent|agency_affiliated) / `agency`.
- `admin` 은 **글로벌 단일**(테넌트 개념 없음).
- 카탈로그(`GET /catalog`)는 **활성 상품 전체**를 반환 — 테넌트 스코프 필터 없음.

**개념상 필요한 변화**
- **도매관리자(테넌트) 엔티티 신설** → 첫 행 = LALAS.
- **도매상이 도매관리자에 소속**(예: `wholesalers.manager_id` 류) — 도매상은 관리자 하나에 속함(1:n). ⚠️ **단, 모든 데이터를 도매관리자(테넌트) 단위로 스코프 가능하게** 설계할 것 — 1차는 LALAS 단일 테넌트로 동작해도, **먼 미래 다중 도매관리자**가 붙을 때 안 갈아엎게.
- **셀러도 도매관리자에 연계**(연계되면 그 관리자의 모든 도매 상품 노출).
- **카탈로그를 "셀러가 연계된 도매관리자" 스코프로 필터**.
- **`admin` 권한을 테넌트(도매관리자) 단위로** 재정의 — 자기 테넌트의 도매·셀러만 승인/관리.

## 6. 우선순위 구분 — 딱 2단: **지금(1차)** vs **먼 미래**
> 사장님 확정: **"후순위 = 먼 미래"**. 중간 단계 없음. 1차에 안 들어가는 건 전부 먼 미래로 묶는다.

### 🔵 6-1. 1차 개발 후보 (지금)
- 도매관리자(테넌트) 개념 도입 + **LALAS 시드**.
- `/admin` → **도매관리자 대시보드**로 재편.
- **단일 도매업체 대시보드 분리**.
- 도매관리자 대시보드 **상품관리 탭**(소속 도매 **전체 합산** 리스트, 도매 출처 표시).
- **셀러 ↔ 도매관리자 연계 → 그 관리자의 모든 도매 상품 노출**.
- **가입 승인 흐름**을 도매관리자 단위로.
- 가격: **일반 셀러=도매가 / 에이전시 소속 셀러=미노출** (기존 규칙 유지).

### ⚪ 6-2. 먼 미래 (= 후순위 전부 포함)
- **도매관리자(테넌트)가 여러 개로** — LALAS 외 다른 에이전시들에게 제품을 팔아 각자 도매관리자 테넌트가 됨(다중 테넌트 실운영). **1차는 LALAS 단일.**
- **셀러별 도매 제한 가시성** (예: 셀러 1 은 A·B 만 보고 C 는 못 봄).
- **에이전시 실운영** — 에이전시가 자기 소속 셀러를 직접 관리(현재 TODO Phase 2 "조직 위임 관리"와 연결).
- **수익화 / 스케일 확장**:
  - **도매관리자** 구독료
  - **도매업체** 구독료
  - **셀러**의 주문 내역으로 거래액(거래 수수료)
  - (더 나중) **셀러에게도 직접 과금**

## 7. 열린 질문 (다음 세션이 결정해야 할 것)
1. **셀러 소속의 표현**: 개념상은 "도매상 1:n 셀러"인데, 1차 동작은 "셀러 ↔ 도매관리자 연계 → 전체 도매 노출"이다. 데이터 모델에서 셀러를 **도매상에 붙일지, 도매관리자에 붙일지** (후순위 "셀러별 도매 제한"을 고려하면 도매관리자 연계 + 추후 도매별 화이트리스트가 자연스러움).
2. **기존 `agency` 역할/테이블** ↔ 새 "에이전시-운영형 도매관리자"의 관계 정리 (에이전시가 곧 도매관리자 테넌트가 되는가? 아니면 별개?).
3. **멀티테넌트 격리 수준** — RLS vs 앱레이어 스코프 (현재 service key 라 앱레이어 가드 중).
4. **도매관리자 대표 계정 ↔ `admin` 역할 매핑** (대표 1명이 운영).
5. 셀러가 **여러 도매관리자에 동시 연계** 가능한가? (기본 가정: 1개).
6. LALAS 가 "일반 셀러는 직접 관리, 에이전시는 수수료" 두 갈래를 **한 테넌트 안에서** 어떻게 구분 관리하는가 (price_visibility 로 충분한가).
