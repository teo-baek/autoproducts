ezmerce DB 관계도7개 테이블 · 7개 ENUM · 감사(누가)·soft delete 컬럼까지

"도매업체가 상품을 올리고, 셀러가 역할에 맞는 가격으로 카탈로그를 본다"를 표로 옮긴 모습. 도매업체와 에이전시는 다른 주체라 테이블도 분리, 모든 테이블은 soft delete + 감사 컬럼을 가집니다. 선은 1 → N.

한 장으로 보는 연결

PK 기본키FK 외래키U 유니크 ★ 최근 추가🕓 공통 감사/삭제 컬럼 점선=1:1, 화살표=1:N분홍=에이전시

🕓 모든 테이블 공통 컬럼 (감사 + 생명주기)

created_at 생성시각 updated_at 수정시각 (트리거 자동) created_by → profiles (누가 생성) updated_by → profiles (누가 수정) deleted_at soft delete (NULL=살아있음)

아래 표 카드에는 각 테이블 고유 컬럼만 적고, 이 5개 공통 컬럼은 카드 맨 아래 🕓 줄로 요약했습니다. (upload_jobs는 created_by 원래 보유 / profiles는 approved_by 추가 보유)

한눈에 이해하기

말로 풀면

🏢도매업체 ≠ 에이전시

다른 주체라 표를 나눔. wholesalers=상품 파는 쪽, agencies=셀러 관리하는 쪽. products.wholesaler_id는 도매업체만 가리킴(타입 안전).

👤사람은 어디 소속?

계정은 profiles. 도매 직원은 wholesaler_id, 에이전시 직원·소속 셀러는 agency_id로 소속을 가리킴.

📦업체 → 상품 → 옵션·이미지

도매업체 1 → 상품 N, 상품 1 → SKU(가격·재고) N + 이미지 N. 품번 충돌은 글로벌 platform_code로 차단.

🔍누가 어떤 가격을 보나

profiles.price_visibility(관리자 설정)로 결정 — 미설정이면 셀러 유형 기본값(라이브셀러→도매가, 에이전시→판매가, 소속셀러→미노출).

🗑️삭제는 지우지 않는다 (soft delete)

모든 테이블 deleted_at. 진짜 DELETE 안 하고 시각만 찍음 → 복구·감사 가능. 부모를 지우면 자식도 트리거가 함께 처리. 조회는 항상 살아있는 행만.

🕵️누가 뭘 했나 (감사)

모든 테이블 created_by/updated_by(→profiles) + created_at/updated_at. updated_at은 수정 때 트리거가 자동 갱신.
