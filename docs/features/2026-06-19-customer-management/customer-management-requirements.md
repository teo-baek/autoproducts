# 요구사항: 고객 관리 (Customer Management) — 1차

> **다음 단계 안내**: 이 문서는 PRD (기획 단계 요구사항만) 입니다. 다음 단계로 `tech-design` skill (`/tech-design`) 을 호출해서 `customer-management-tech-design.md` (기술 설계서) 를 만드세요. 기술 결정(DB 스키마/엔드포인트/컴포넌트)이나 구현 세부는 여기 박지 마세요.

## 1. 배경/목적

- **1차 배포에 도매 관리자 콘솔의 "고객 관리" 화면을 추가**한다. 현재 `/customers`(`apps/web/src/app/(dash)/customers/page.tsx`)는 "준비 중" 자리표시자만 있다.
- 기준 디자인 = `ezmerce_클로드디자인/project/Admin.dc.html` 의 **고객 관리** 화면(`도매 관리자 콘솔 > 고객 관리`).
- ⚠️ **범위 제약(사장님 결정 2026-06-19)**: 주문 시스템(주문/결제/정산)은 **후순위(Phase 2)** 다. 그래서 디자인 고객관리 컬럼 중 **주문 의존 항목(누적주문·최근주문·미수금·정산·입금처리·자동등급)은 1차에서 제외**하고, **거래처 관리(목록·정보·등급(수동)·가격노출·가입상태)** 만 만든다.
- ⚠️ **사용 주체 = 도매관리자(`admin`) + 도매(`wholesaler`) 둘 다 (사장님 결정 2026-06-19).** 계층은 `도매관리자 > 도매업체 > 소매(거래처)` 이고 **위에 있는 주체가 아래 전부를 본다**: **도매관리자 = 도매업체 + 소매 거래처를 모두** 관리(테넌트 전체), **도매 = 자기에게 배정된 소매만**. 소매(거래처)는 **특정 도매업체에 배정**된다(소매↔도매 **배정 관계는 신규** — 현재 데이터엔 소매-도매 연결이 없음).
- 동시에 **1차 미운영 메뉴(주문관리·카탈로그관리·POS) 버튼을 숨겨** 콘솔을 1차 범위로 정리한다.
- 거래처 목록/가격노출은 기존 백엔드(`GET /admin/accounts`, `POST /admin/accounts/{uid}/price-visibility`)와 멀티테넌트 스코프(`manager_id`)를 재사용한다.

## 2. 사용자 스토리 / 시나리오

- **도매관리자(admin)**로서, **내 밑의 도매업체와 소매 거래처를 모두** 한 콘솔에서 보고 싶다 — 도매사 목록 + 테넌트 전체 소매 풀(누가 어느 도매 소속인지·미배정 포함), 담당자/연락처/등급/가격노출/가입상태까지. (왜: 폐쇄망 전체를 총괄 관리하려고)
- **도매(개별 도매업체)**로서, **나에게 배정된 소매 거래처만** 보고 관리하고 싶다 — 다른 도매의 고객은 절대 보이면 안 된다. (왜: 도매 간 고객 격리)
- **도매 관리자**로서, 거래처별 **가격 노출 권한(도매가/판매가/미노출)**을 화면에서 설정하고 싶다. (왜: 셀러 유형별 가격 차등 노출을 직접 제어 — 지금은 백엔드만 있고 UI가 없음)
- **도매 관리자**로서, 거래처에 **등급(VIP/일반/신규)**을 수동으로 매겨 분류하고 싶다. (왜: 1차엔 주문 데이터가 없어 자동 산정 불가 → 수동 라벨로 관리)
- **도매 관리자**로서, 1차에 안 쓰는 메뉴(주문/카탈로그/POS)는 화면에서 안 보였으면 한다. (왜: 빈 "준비 중" 메뉴로 인한 혼란 방지)

## 3. 기능 요구사항 (FR)

- **FR-1 (소매 거래처 테이블)**: `/customers` 에 **소매 거래처 목록 테이블**을 표시한다. 컬럼 = `거래처명(+아바타) | 담당자 | 가격노출 | 가입상태 | [상세]`. **도매관리자 뷰에는 `연결 도매`(연결 수 = 테넌트 전체 도매 − 취소) 컬럼을 추가**(도매 뷰엔 불필요). (등급 컬럼은 1차 제외 — FR-4 / 디자인의 `누적주문·최근주문·미수금`도 제외)
- **FR-1b (도매업체 목록 — 도매관리자 전용)**: 도매관리자 뷰에는 **소매 거래처뿐 아니라 도매업체 목록도** 함께 본다(탭으로 `소매 거래처` ↔ `도매업체` 구분). 도매업체 컬럼 = `도매업체명 | 사업자번호 | 등록일 | 연결 소매 수`. 도매업체 **가입 승인 자체는 기존 `/admin` 흐름 유지**. 도매 뷰에는 도매업체 목록이 없다.
- **FR-2 (역할별 보이는 대상)**: 고객관리는 **도매관리자(`admin`)와 도매(`wholesaler`) 둘 다 접근**하되 **보이는 대상이 역할별로 다르다** — **도매관리자 = 도매업체 목록(FR-1b) + 테넌트(`manager_id`) 전체 소매 풀(FR-1)**, **도매 = 테넌트 소매 − 자기에게 취소된 소매**(기본 전부 연결, FR-2b). 데이터: 도매관리자 소매 풀은 테넌트 스코프 조회(이메일/에이전시명 보강), 도매업체 목록은 테넌트 소속 `wholesalers`, **도매용 소매 조회는 테넌트 소매에서 취소분만 제외하는 신규 경로**(테넌트 격리 보장). 소매 가입상태(`pending/approved/rejected`)를 함께 표시한다.
- **FR-2b (매칭 취소 — opt-out, 사장님 결정 2026-06-20)**: 기본은 **테넌트 안 모든 소매↔도매가 연결**돼 있다(소매는 그룹 도매를 다 보고, 도매도 그룹 소매를 다 본다). 도매관리자는 **특정 소매↔도매 매칭을 취소(거래 안 함)**하거나 **복원**할 수 있다(소매 상세에서 도매별 `연결됨/취소됨` 토글). 취소된 쌍만 예외로 빠진다 → 그 도매의 목록에서 해당 소매가 사라진다. (이전의 '배정[opt-in]'에서 '취소[opt-out]'로 반전. 취소 주체 = **도매관리자만**.)
- **FR-3**: **검색(거래처명·담당자)** 으로 목록을 좁힐 수 있다.
- **FR-4 [1차 제외 — Phase 2]**: ~~거래처별 등급(신규/일반) 수동 설정~~ → **등급은 1차에서 제외**(사장님 결정 2026-06-20). 1차엔 주문 데이터가 없어 등급의 **기준이 없고**(신규/일반을 무엇으로 가르는지 불명) **기능도 없음**(가격 영향 0). 화면에서 숨기되 **DB 칸(`profiles.tier`)·백엔드 엔드포인트는 forward-compat 로 보존**(잠자는 상태). **주문 시스템 도입 2차에 "VIP/일반/신규 자동 등급"으로 부활.**
- **FR-5**: 거래처별 **가격 노출 권한(`wholesale`/`retail`/`none`)을 설정**할 수 있다. 기존 `POST /admin/accounts/{uid}/price-visibility` 재사용. 가격은 **서버 권위(`visible_price()`)** 원칙을 그대로 따른다(프론트 추론 금지).
- **FR-6**: **[상세]** 클릭 시 거래처 상세 패널을 연다. 표시 = 기본정보(거래처명/담당자/연락처/이메일/가입일/가입상태) + 등급 설정 + 가격노출 설정 + **거래 메모(선택)**. **주문이력·미수금·정산이력·입금처리·거래이력 CSV는 1차 제외**(Phase 2).
- **FR-7**: 좌측 메뉴에서 **"주문 관리", "카탈로그 관리" 항목을 숨기고**, 헤더의 **"POS" 버튼을 숨긴다**. (라우트·코드는 남겨두고 **노출만 차단** — Phase 2 복원 용이)
- **FR-8**: 조건에 맞는 거래처가 없을 때 빈 상태 안내("조건에 맞는 거래처가 없습니다")를 표시한다.

## 4. 비기능 요구사항 (NFR)

- **가격 노출 = 서버 권위.** 프론트는 서버가 준 값만 표시(`price:null`=「가격 문의」, 0원/추론 금지). CLAUDE.md §가격노출 준수.
- **테넌트 격리 + 취소 격리.** ① 다른 도매관리자(테넌트)의 거래처가 절대 보이면 안 됨(`manager_id` 스코프). ② **도매는 '취소된' 소매는 조회·변경 불가**(취소 격리). ※ 기본은 테넌트 소매 전부 연결이라 도매↔도매 완전 격리는 아님 — 관리자가 취소한 쌍만 가려진다. service-key가 RLS를 우회하므로 **앱레이어가 책임**진다([[wholesaler-image-isolation]] 와 동일 클래스).
- **soft-delete 준수.** 모든 조회는 `WHERE deleted_at IS NULL`.
- **디자인 시스템 준수.** `apps/web/design/DESIGN-SYSTEM.md` + `ezmerce-tokens.css` 토큰 사용. 등급/상태 배지는 시맨틱 토큰(승인 초록/대기 앰버/거절 빨강/등급 연보라 등).

## 5. 범위 밖 (Out of Scope) — Phase 2+

- 주문 이력·누적주문·최근주문·**미수금·정산 이력·입금 처리·거래이력 CSV**(주문 시스템 의존, 대화 중 명시 제외)
- **자동 등급 산정**(주문량 기반)
- 거래처 **직접 생성/초대** — 가입 승인 흐름은 기존 `/admin` 페이지 유지
- **주문관리·카탈로그관리·POS 화면 자체 구현** — 1차는 메뉴/버튼 숨김만(FR-7)
- 에이전시 셀프 운영(소속 셀러 위임 관리)

## 6. 수용 기준 (Acceptance Criteria)

- AC-1: `/customers` 접속 시 "준비 중" 대신 **거래처 목록 테이블**이 보인다(도매관리자·도매 모두).
- AC-2a: **도매관리자**로 보면 **도매업체 목록 + 테넌트 전체 소매**가 모두 보이고(탭 구분), 소매 각 행에 `연결 도매 수`(전체−취소)가 보인다.
- AC-2b: **도매**로 보면 **도매업체 목록은 없고**, **테넌트 소매 − 자기에게 취소된 소매**가 나온다(취소 없으면 전부, **타 테넌트 계정은 0건**).
- AC-2c: 소매↔도매 매칭을 **취소/복원**하면 그 도매의 목록에서 해당 소매가 **사라지거나 다시 나타난다**.
- AC-3: 검색으로 목록이 **필터링**된다.
- AC-4 [1차 제외]: 등급 변경은 1차 제외(FR-4, Phase 2 자동등급).
- AC-5: 거래처 가격노출을 바꾸면 저장되고, 그 셀러의 **카탈로그/엑셀 가격 표시가 바뀐다**(서버 `visible_price()` 경유).
- AC-6: 좌측 메뉴에 **주문관리·카탈로그관리가 안 보이고**, 헤더에 **POS 버튼이 안 보인다**.
- AC-7: 거래처 상세 패널에 **주문/미수금/정산 항목이 없다**(1차).
