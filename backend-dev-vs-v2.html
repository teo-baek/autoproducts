dev vs v2-dev

화면은 그대로인데 뒤(백엔드)가 다릅니다. feature/dev는 "열린 데모", v2-dev는 "관문을 세운 운영판" — 무엇이 바뀌었는지 git 사실 기준으로 비교합니다.

1
architecture

핵심 차이 — "관문"이 생겼다

기존 dev는 프론트가 활짝 열린 DB에 직통으로 붙었어요. v2-dev는 그 사이에 검문하는 백엔드(FastAPI)를 끼워 넣었습니다.

feature/dev

열린 데모

🔓 누구나 들어가는 구조 (인증 없음)
Next.js · Expo 프론트role 토글 (로그인 없음)
직통
🔓 Supabase DBRLS = USING(true) · 누구나 읽기/쓰기/삭제

3
trade-off

그래서 무엇을 맞바꿨나

기존 dev는 빨리·다 보여주되 무방비, v2-dev는 느리지만 운영 가능한 견고함. 대신 v2-dev는 아직 미완 구간이 있습니다.

feature/dev

"데모 완성본" — 화면은 다 됐고, 보안은 비었다
화면 완성도높음
운영 안전성낮음
⚠️ DB 활짝 열림 · 로그인 없음 → 실서비스엔 위험

v2-dev

"운영판" — 척추를 제대로 세우는 중
운영 안전성높음
화면·연결 완성도진행 중
🔧 업로드 API·일부 화면 미완 + 새 백엔드 ↔ 기존 프론트 아직 미연결

backend/notebooks(_build_notebook): /uploads/* 미구현 · routers(admin/products/catalog/public) 구현

dev vs v2-dev 백엔드 비교 · git 실측 기준 (merge-base · diff --stat · schema 검사)
feature/dev = 열린 데모(화면 ✅·보안 ❌) → v2-dev = 관문 세운 운영판(보안 ✅·연결 진행중)
